RAG Step by Step

Build a question answering app on your own laptop

Everything here runs on your machine. Ollama runs the AI models locally, and a few small Python files ask them questions about three short documents: a library handbook, a pool guide and a recycling guide. Set up once, then work through the steps.

✓No cloud account ✓No API key (except step 10) ✓No cost per question ✓Works offline after setup

Learn

What is RAG?

RAG (retrieval augmented generation) lets a model answer from your own documents. You load the documents, split them into chunks, embed them, retrieve the chunks that match the question, give those to the LLM, and get the answer.

  1. 1LoadRead the documents.
  2. 2ChunkSplit them into small pieces.
  3. 3EmbedTurn each piece into numbers that capture its meaning.
  4. 4RetrieveFind the pieces closest in meaning to the question.
  5. 5LLMSend the question and those pieces to the model.
  6. 6AnswerThe model answers from those pieces.
One question from the library handbook
questionCan I drink water in a reading room?
retrievedFood and drinks are not allowed in the reading rooms, except for water in closed bottles.
answerYes, if the water is in a closed bottle.

Build on it

The twelve steps

Build and run one file at a time, in number order. Each file adds one idea to the last.

  1. Step 1Ask the LLMSend a question, get a response.
  2. Step 2Add a promptTell the model how to answer.
  3. Step 3Hard-coded contextGive the model facts to answer from.
  4. Step 4Full contextRead every document from files. No RAG yet.
  5. Step 5Chunk the documentsCut the documents into small pieces.
  6. Step 6Add metadataLabel each chunk with where it came from.
  7. Step 7Embed the chunksTurn each chunk into a vector of numbers.
  8. Step 8Search by meaningFind the closest chunk to a question. No LLM.
  9. Step 9Search and answerSend the closest chunk to the LLM.
  10. Step 10Answer with OpenAIStep 9 with an OpenAI model writing the answer.
  11. Step 11Vector storeStore, filter and save the vectors.
  12. Step 12EvaluationCheck the answers against expected ones.

Step 1

Ask the LLM

01_ask_llm.py

The starting point: send a question to the model through LangChain and print what it sends back. No documents yet.

from langchain_ollama import OllamaLLM

llm = OllamaLLM(model=CHAT_MODEL, base_url=OLLAMA)

# Defined once, outside the question loop
def ask_generate(prompt):
    return llm.invoke(prompt)  # returns the answer text directly

# Inside the loop, for each question
answer = ask_generate(question)

Ask it anything. It answers from what it learned in training.

Run step 1
> uv run 01_ask_llm.py

Next: Step 2, Add a prompt →

Step 2

Add a prompt

02_add_prompt.py

Step 1 sent the question on its own. This step puts it inside a prompt: instructions that tell the model how to answer, with the question at the end.

# Written once at the top, under the settings
instructions = """Answer the question in two sentences or fewer, in plain language.
If you are not sure of the answer, say "I don't know"."""

# Defined once, outside the question loop
def ask_generate(prompt):
    return llm.invoke(prompt)

def build_prompt(question):
    return f"""{instructions}

Question: {question}"""

# Inside the loop, for each question
prompt = build_prompt(question)
answer = ask_generate(prompt)

The prompt and the model call each live in their own function, outside the loop, so anything else in the program can reuse them. The later steps use the same idea for every stage, such as search() and build_prompt().

Ask the same question as in step 1 and compare. The answer should now be short and plain. The program prints the full prompt first, so you can see exactly what the model receives.

Run step 2
> uv run 02_add_prompt.py

Next: Step 3, Hard-coded context →

Step 3

Hard-coded context

03_hardcoded_context.py

The model has never seen our library handbook, so on its own it can only guess about it. This step gives it some facts to answer from: two paragraphs of the handbook, typed straight into the code as context.

context = """The library is open from 9am to 8pm Monday through Thursday ...

Food and drinks are not allowed in the reading rooms, except for water in closed bottles. ..."""

What's new compared with step 2: the instructions change to two rules about the context, and build_prompt() adds the context between the instructions and the question.

# Written once at the top, under the settings
instructions = """Answer the question using ONLY the context below.
If the answer isn't in the context, say "I don't know"."""

# Defined once, outside the question loop.
# The parts are joined with a blank line between them.
def build_prompt(context, question):
    return "\n\n".join([instructions, f"Context:\n{context}", f"Question: {question}"])

# Inside the loop, for each question
prompt = build_prompt(context, question)
answer = ask_generate(prompt)

The rules keep the model to the context. Without them it would mix in what it learned in training, or make an answer up.

Try askingExpected answer
Can I drink water in a reading room?Yes, if the water is in a closed bottle.
Is the library open on Sunday?No, it is closed on Sundays.
Can a 15-year-old borrow a laptop?I don't know. Laptops aren't in this context.

The last question shows the "I don't know" rule working. The model only has two paragraphs, so the honest answer is that it doesn't know.

Step 4

Full context

04_full_context.py

Typing the context into the code doesn't scale. This step reads it from files instead: every Markdown file in docs, joined into one context. build_prompt() and the question loop are the same as step 3. No RAG yet.

# Read the entire contents of every Markdown file
documents = []
for file in Path("docs").glob("*.md"):
    text = file.read_text(encoding="utf-8")
    if text.strip():
        documents.append(text)

# Combine all document contents into one context
context = "\n\n".join(documents)
Try askingExpected answer
Can I drink water in a reading room?Yes, if the water is in a closed bottle.
Can a 15-year-old borrow a laptop?No. Laptop borrowers must be members aged 18 or older.
When is the pool closed for cleaning?Every Wednesday from 1pm to 3pm.
Is it open on Sundays?It depends which place you mean: the library is closed on Sundays, and the pool is open from 8am to 6pm.

The laptop question got "I don't know" in step 3. Now all three documents are in the context, so the model can answer it. The Sunday question shows a new problem: with several documents, a vague question can match more than one of them. Before each answer the program prints the full prompt, documents included, so you can see everything that was sent.

GoodThe simplest version. Nothing can be missed. Works well while the documents are small, like our three short guides.
ProblemThe prompt grows with every document, so it gets slower, costs more and answers get worse as the useful sentence gets buried. Every model can also read only so much text at once (its context window); past that, text gets cut off.

The notes at the bottom of the file list what people try next:

  • Keyword search: needs the exact words, so "change credentials" misses "change password".
  • Vectors in a regular database: matches meaning, but compares every row without an index.
  • Vector database and RAG: finds the closest chunks fast and sends only those.

Step 5

Chunk the documents

05_chunk_documents.py

Step 4 sends every document with every question. To send only the useful parts, first cut the documents into small pieces, called chunks. This step splits each document wherever there is a blank line, so each chunk is one section with its heading.

# Split each document into chunks wherever there is a blank line
chunks = []

for document in documents:
    for paragraph in document.split("\n\n"):
        if paragraph.strip():
            chunks.append(paragraph.strip())

It prints every chunk and how many there are, then exits. There are no questions and no model in this step.

This works because each section in our documents is one short paragraph. Smarter splitting comes later, in roadmap item 4.

Step 7

Embed the chunks

07_embed_chunks.py

Step 6 plus one stage: Embed. The embedding model reads each chunk and returns a vector, a list of 768 numbers that captures what the chunk means. Chunks with similar meaning get similar numbers.

embedding_model = OllamaEmbeddings(model=EMBED_MODEL, base_url=OLLAMA)

# One call turns every chunk's text into a vector
vectors = embedding_model.embed_documents([chunk.page_content for chunk in chunks])

It prints each chunk's text, then the length of its vector and its first 8 numbers. One number means nothing on its own. Only comparing whole vectors tells you how close two meanings are, which the next steps do.

Production

Error handling

The step files leave out error handling to stay short. Any failure prints a traceback and ends the program, so one failed call loses the whole session. This section lists what can go wrong and what a production app does about it.

What production apps do

  1. Check at startup. Confirm Ollama is reachable and the model exists before taking questions, so setup problems show once, clearly.
  2. Catch specific errors around the model call. Show a clear message, log the details, and keep the loop running.
  3. Don't catch everything. A bare except Exception: pass hides real bugs. Catch the errors you expect and let unexpected ones surface.
  4. Retry only what might succeed. Use the rules below.
  5. Set a timeout. A hung request should end with a message, not freeze the app.
  6. Exit cleanly. Ctrl+C and end of input should end the program without a traceback.
  7. In a web app, also return a proper HTTP error to the browser and log a request ID, so you can find the failure later.

Retry or not?

Retry when both are trueThe failure is temporary: connection refused or dropped, a timeout, status 500 or above, or 429 "too many requests" on hosted APIs.

Repeating is safe: asking a question changes nothing, so sending it twice does no harm.
Don't retry whenThe request itself is the problem: status 400 to 499, such as 404 model not found, 400 bad request, 401 or 403 not allowed. The same request fails the same way.

Or the call has side effects, such as booking a room or sending an email, unless the service is built to ignore repeats.

How to retry: two or three attempts at most, waiting longer each time (1 second, then 2), then give up with a clear message. In apps with many users, add a small random extra wait so they don't all retry at the same moment.

An example for step 1. It was tested here: with Ollama stopped it tried three times and then gave up, and a missing model raised its 404 at once without retrying.

import time
from httpx import ConnectError, ReadTimeout
from ollama import ResponseError

# Check the model exists at startup, and give each call 120 seconds
llm = OllamaLLM(model=CHAT_MODEL, base_url=OLLAMA,
                validate_model_on_init=True, client_kwargs={"timeout": 120})

def ask_generate(prompt, attempts=3):
    for attempt in range(1, attempts + 1):
        try:
            return llm.invoke(prompt)
        except (ConnectError, ReadTimeout) as error:
            failure = error                    # temporary: worth another try
        except ResponseError as error:
            if error.status_code < 500:
                raise                          # 400 to 499: fails the same way again
            failure = error                    # 500 and above: may clear
        if attempt < attempts:
            time.sleep(2 ** (attempt - 1))     # wait 1 s, then 2 s
    raise failure

# In the question loop
try:
    answer = ask_generate(question)
except (ConnectError, ReadTimeout):
    print("Can't reach Ollama right now. Check it's running, then ask again.")
    continue
except ResponseError as error:
    print(f"Ollama returned an error: {error}")
    continue

Wrap the whole while True: loop in try: ... except (KeyboardInterrupt, EOFError): print("Goodbye") to exit cleanly.

Roadmap

The twelve steps give you a working RAG app. These improvements take it toward a production app, one at a time.

One change at a timeRun 12_rag_evaluation.py before and after each improvement, and compare the two result files.
Add the proofEach improvement adds the questions that show it working to the evaluation set. Step 12's word check can pass a wrong answer, so read the answers too, or add a second LLM that judges each answer against the expected one.

See what it's doing

  • 1

    Sources with every answer

    Steps 8 to 11 already print each found chunk's score, chunk ID and section. What's left: put each chunk's title and section into the prompt, and show them under the answer, such as "Source: Mapleford Community Pool Guide > Entry fees".

    Done whenevery answer shows which guide and section it came from.

Trustworthy answers

  • 2

    Controlled answer generation

    Lower the temperature, fix the seed and set the context window size yourself. On this laptop Ollama gave llama3.2 a 4,096-token window, though the model supports 131,072. Then, as a separate change, move the rules into a system message and improve them.

    Done whena question with a rule and an exception, such as water in a reading room, gets the same correct answer across repeated runs, while missing facts still get "I don't know".

  • 3

    Answers with citations

    Label each retrieved passage, like [1] and [2], and ask the model to cite the labels it used. Check in code that every cited label was actually sent.

    Done whencitations point to retrieved passages that support the answer.

Find better context

  • 4

    Better Markdown chunking

    Group text by headings, and split sections that are too long.

    Done whenheadings, rules and their exceptions stay together in useful chunks. In our documents every section is one paragraph, so the gain shows on longer documents.

  • 5

    Keyword search

    Build a keyword retriever over the same chunks. It's the baseline for improvements 6 and 9.

    Done whenexact-word questions such as "laptop" or "batteries" find the right chunk, and you can see where it fails, such as "change my password" when the text says "update credentials".
