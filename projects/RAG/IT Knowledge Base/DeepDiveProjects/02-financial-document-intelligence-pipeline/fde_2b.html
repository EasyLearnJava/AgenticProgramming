Project 2: Financial Document Intelligence Pipeline RAG

Description

Build a RAG pipeline that answers questions across financial documents - SEC filings, earnings call transcripts, insurance claims, or loan documents. Implement two chunking strategies (fixed-size vs. semantic chunking) and compare retrieval quality on the same set of queries. Add a reranking step and measure the improvement. This project is particularly relevant for anyone working in financial services, insurance, or regulated industries, but the techniques apply to any domain with dense, structured documents. This project now has code and n8n in the Week 2 project list.

Best For

Data Scientists/Analysts (financial analysis), Finance roles (Wells Fargo, JPMC, Citi, Morgan Stanley, NYLife), Architects (pipeline design), Consultants (client financial analysis).

2B in one paragraph. The notebook downloads Apple's two latest annual reports (10-K filings) from SEC EDGAR, the SEC's filing system, as “full submission” text files. Each file holds the 10-K plus everything filed with it: about 70 XBRL viewer pages (the financial statements rendered as web pages), a JSON metadata file, exhibits, and ZIP and image files encoded as text (uuencoded). It strips the HTML and cuts the text two ways. Fixed-size chunking cuts every 512 characters (64 overlap). Semantic chunking splits the text into sentences, embeds each with its neighbours, and cuts where the meaning shifts most: at distances above the 65th percentile. Both sets are embedded with BAAI/bge-base-en-v1.5, which reads at most 512 tokens of each text, and stored in one Pinecone index, one namespace (partition) each. A question is embedded the same way and matched against the chunks: a bi-encoder search that returns the top-k most similar. A reranker (a cross-encoder) then reads each question-and-chunk pair together and re-sorts them. gpt-4o-mini writes the answer from three chunks. Three set-ups are compared on 10 questions: A fixed, top 3; B semantic, top 3; C semantic, top 10 re-ranked to 3. RAGAS scores them with an LLM as judge: faithfulness (is the answer supported by the chunks?), context precision (are the chunks relevant, best first?) and context recall (do the chunks hold everything the reference answer needs?). The golden set is the agreed list of test questions with expected answers and sources. XBRL is the machine-readable tagging of the financial statements that every 10-K and 10-Q carries.

2.1How an FDE reads this brief

  1. Find the real deliverable. “compare retrieval quality on the same set of queries” and “measure the improvement” make the output an experiment: a comparison someone can trust. The pipeline is the apparatus. So the experiment design (what changes, what stays fixed, what is measured) comes first.
  2. Pick the document type with the customer; it decides everything else. The brief offers four. SEC filings are public and machine-tagged. Earnings call transcripts are conversational and usually licensed from a vendor. Insurance claims and loan files are private, full of personal data, and often scanned forms. 2B chose the easiest of the four, which is a fine start if everyone knows it was a choice.
  3. Look at the data before tuning anything. Open the files you are about to index. In 2B the “10-K” is a 9.5 MB EDGAR submission package, and the annual report's text is about a tenth of what gets indexed (2.7).
  4. In finance a number is only right with its company, period, unit and source. “$391,035” is wrong without “million”, “fiscal 2024” and “Apple 10-K, page 22”. That decides the metadata and the citations, and whether some questions belong to a database lookup instead of RAG.
  5. A comparison is only fair if one thing changes at a time. Same corpus, same filter, the same amount of text handed to the model, enough questions to see past noise, and a judge whose blind spots you know.
  6. Regulated means repeatable and explainable. US banks validate models under model risk management guidance (the Federal Reserve's SR 11-7, issued jointly with the OCC as Bulletin 2011-12); ask Model Risk Management (MRM) whether a GenAI tool is in scope. Validators expect a run that can be repeated from pinned data, code and model versions, with its run-to-run spread measured, because LLM calls are not repeatable bit for bit, even at temperature 0.

What the table cannot show

  • A → B changes several things at once: where chunks end; how long they are (431 characters against about 2,000 as stored); how much text the model gets (three average chunks are about 1,300 characters in A and 6,000 in B); which text survives the filter, which judges small and large chunks differently (by our check, it drops 11 of the 13 fixed chunks holding the Americas figure with its label); and how much of each chunk bge-base sees, since it reads 512 tokens. The win cannot be credited to semantic boundaries alone. B → C changes one thing, the reranker, and is the cleaner step. In code
  • The docs' explanation of A's zero does not hold. The solution kit says fixed chunks cut tables so that “none of the 12,142 chunks was useful”. Our re-run of cells 21–25 reproduces their counts exactly (14,119 raw, 12,142 kept, 431 average) and finds each reference figure with its row label in kept chunks: 19 hold both “Total net sales” and “391,035”. An offline re-run of set-up A's search (the same chunks, the same bge model, exact cosine search instead of Pinecone) puts no chunk holding the figure with its row label in the top 3 for any of the eight figure questions; the first such chunk ranks between 5th and 137th. The top 3 are 10-K prose, mostly about 2024, not noise. Cell 39 prints the fixed-size top result for three of the evaluation questions, and our top result matches the notebook's for all three. So for the eight figure questions, A's 0.00 is a ranking failure; our reading is that number-dense table chunks (about 500 characters, a fifth of them digits) lose to shorter prose sharing the question's words. With k = 10, four of the eight would have been found. Checked

Each EDGAR full submission bundles the 10-K with about 70 XBRL viewer pages, a JSON metadata file, XBRL linkbases, exhibits, and uuencoded ZIP and image files (plus an Excel workbook in the FY2024 submission). An FDE's version keeps the idea and changes the design (figure 11 draws the result):

  1. Fix the corpus first. Index the 10-K document only, pinned by accession number, with fiscal year, form and section on every chunk.
  2. Change one thing at a time. Fixed at 512 and at about 2,000 characters, and semantic, each with and without the reranker: all chunking the same text, filtered by part of the submission before chunking rather than after, with chunks kept inside the embedder's and reranker's 512-token windows, and every set-up given the same character budget.
  3. Grow the golden set to 30–50 questions written with analysts: figures from both years, year-on-year comparisons, a calculation, narrative questions, questions the filings don't answer, and a wrong premise. Each has an expected answer and an expected section, signed off by a finance SME.
  4. Lead with deterministic, budget-neutral metrics. Did the expected section reach the model at a fixed character budget? Does the answer's figure match the reference exactly? Then RAGAS, with a judge calibrated against a human-labelled sample.
  5. Repeat each run three times and report per question; hold out a third of the golden set from all tuning; before running, write down the decision rule: a gain counts only if it exceeds the run-to-run spread and holds question by question. Store every run's results.

2.10What to take away

  1. The deliverable is a trustworthy comparison: decide what changes, what stays constant and what counts as a win before building.
  2. Open the files before tuning. About 9% of 2B's fixed-size index is annual-report text; no chunking strategy fixes indexing the wrong text.
  3. Check the story behind a striking number, and measure your own counter-story too. A's 0.00 was explained as broken tables; the answers were in the fixed index, and an offline re-run of A's search showed, for the eight figure questions, the answer chunks ranking below 10-K prose about the same year.
  4. In finance, period, unit and source are part of the answer: they belong in the metadata, the filters and the citations, and some figures belong to a structured lookup, not RAG.
  5. Regulated customers need repeatability: pinned filings, packages and model versions, a notebook that runs top to bottom, repeated runs with their spread, and a judge whose errors you have measured.
