The Gen Academy · Week 2 · deep-dive projects 2A–2D

Where each project's input comes from

For each of the four projects: the data the system answers from, how that data gets in, and where the questions and test sets come from. Every figure comes from each project's code or saved run output at the commits listed in section 3, or was recounted from them for these analyses; the 2B composition figures come from the 2B analysis's own check of the same two filings.

The short answer. None of the four connects to a customer's live system. Three answer from small files committed to their repositories, written for the course about made-up organizations (2A, 2C, 2D). One (2B) downloads real public filings when its notebook runs, but it takes each filing's whole submission, so most of what it indexes is not the annual report's text.

2BFinancial Document Intelligence Pipeline The person running the notebook, in code cells (rag_answer(question)); there is no user interface 10 questions with reference answers checked by hand against the 10-Ks (eval_dataset), scored with RAGAS for three set-ups: fixed-size chunks, semantic chunks, and semantic chunks with re-ranking. 4 of the same questions (one slightly reworded) are also run once through the full pipeline as a quick check
